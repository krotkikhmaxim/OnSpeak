## 1. Бизнес-контекст и модель проекта

### Модель монетизации

SpeakUP работает по **гибридной B2C + B2B2C SaaS-модели** с маркетплейсным элементом:
- **Год 1 — B2C**: pay-per-session или подписка, прямая оплата через приложение
- **Год 2+ — B2B2C**: корпоративные HR/L&D-пакеты → предсказуемый ARR

Платформенная природа: SpeakUP не нанимает тьюторов в штат — агрегирует и монетизирует их как marketplace (модель Cambly, не Skyeng).

### Проблема

**Миллионы россиян умеют читать и слушать на английском — но не могут свободно говорить.** Причина — хроническая нехватка живой разговорной практики в безопасной, доступной и on-demand форме. Проблема трёхслойная:

- **Психологический барьер**: страх ошибиться, перфекционизм — два главных блокера говорения по данным Englex
- **Структурный дефицит**: Cambly и Preply ушли из РФ в 2022 году. Ниша on-demand speaking practice (15–30 мин без записи) не закрыта ни одним локальным игроком. Skyeng работает по расписанию (min 45 мин, ~2 500 ₽/урок), italki/Preply недоступны для оплаты из РФ
- **Технологический пробел**: никто не использует ML для подбора тьютора под уровень, акцент и тему за ≤ 30 секунд — ключевой параметр удержания в on-demand-модели

### Рыночные данные

| Метрика | Значение | Источник |
|---------|---------|---------|
| Россиян, изучающих английский | ~20–27 млн чел. | Forbes/Skyeng 2024 |
| Рост интереса к английскому 2025 | +12,1% г/г | Helen Doron / Яндекс Вордстат |
| Рынок EdTech РФ 2024 | 148,8 млрд ₽ (+19% г/г) | Smart Ranking / Forbes |
| Сегмент иностранных языков EdTech | +43% г/г | Smart Ranking |
| TAM (онлайн-обучение EN, РФ+СНГ) | ~7,2–8,8 млрд ₽/год | Smart Ranking |
| SAM (on-demand speaking, незакрытый) | ~1,5–2,5 млрд ₽/год | Cambly-аналогия + кастдев (n=4) |

### Три триггера «Почему сейчас»

1. **Рыночный**: уход Cambly/Preply из РФ оставил незакрытый спрос; интерес к EN впервые за 2 года вырос на +12,1% в 2025
2. **Технологический**: Whisper + GPT-4o стали commodity API в 2023–2025, что позволяет строить персонализированный сервис без NLP-разработки с нуля
3. **Поведенческий**: спрос смещается от «длинных уроков по расписанию» к коротким прикладным on-demand сессиям

### Unit-экономика (цель, год 1)

| Показатель | Baseline (случайный matching) | Цель (ML-matching) |
|-----------|------------------------------|-------------------|
| Rebook rate | 15% | 32% |
| Sessions/MAU | 1,2 | 2,5 |
| ARPU/мес | 600 ₽ | 1 250 ₽ |
| LTV (6 мес) | 3 600 ₽ | 7 500 ₽ |
| CAC | высокий | -66% vs baseline (при MAPE ≤ 15%) |

## 2. ML-система: описание всех задач

### Обзор архитектуры

SpeakUP строится на **5 взаимосвязанных ML-задачах**, закрывающих все ключевые точки жизненного цикла пользователя:

```
ЗАДАЧА 0: Supply-Demand Balancing
    ↓  (привлекаем правильных студентов и тьюторов заранее)
ЗАДАЧА 1: Tutor Matching (ранжирование)
    ↓  (студент начал сессию с подобранным тьютором)
ЗАДАЧА 2: ASR — транскрипция речи
    ↓  (получили текст разговора)
ЗАДАЧА 3: LLM-фидбек (оценка речи)
    ↓  (студент получил разбор ошибок)
ЗАДАЧА 4: Recommendation Engine (следующая сессия)
```

### Ключевые сущности данных

| Сущность | Ключевые атрибуты | Роль |
|---------|-----------------|------|
| **Student** | user_id, CEFR_level, goals[], native_lang, session_history | Потребитель сервиса |
| **Tutor** | tutor_id, specializations[], accent, availability_slots, rating, rebook_rate | Поставщик сервиса |
| **Session** | session_id, student_id, tutor_id, duration, topic, rating, transcript_id | Единица транзакции |
| **Feedback** | feedback_id, fluency_score, accuracy_score, vocabulary_score, recommendations[] | AI-ценность |
| **Match** | match_id, ranked_tutors[], scores[], accepted_tutor_id, wait_time_sec | Артефакт ML |
| **TopicPlan** | plan_id, recommended_topics[], next_session_suggestion | Выход RecSys |
| **MarketBalance** | demand_forecast[slot×level], supply_available, gap_score | Маркетинговые решения |
| **LeadScore** | utm_source, compatibility_score, estimated_LTV | Приоритизация лидов |

---

### Задача 0 — Supply-Demand Balancing (Маркетинговый ML)

**Суть:** стратегический маркетинговый слой, решающий главную болезнь on-demand маркетплейсов — **cold pool problem**. Студент нажимает «Начать» и видит «Тьюторов нет» → уходит навсегда (CAC потрачен, LTV = 0). Предиктивный баланс снижает dropout на старте на 25–40%.

**Подзадачи:**

| Подзадача | Тип ML | Цель |
|---------|--------|------|
| Supply gap prediction | Time-series (LightGBM / Prophet) | Предсказать дефицит тьюторов по слотам и CEFR-уровням |
| Compatibility scoring | Supervised classification (LightGBM) | Оценить P(хорошая пара) по профилю из UTM/анкеты |
| Lookalike targeting | Embedding similarity (Two-Tower) | Похожие на «лучших студентов/тьюторов» в рекламных аудиториях |
| Churn risk | Binary classification | Предсказать уход тьютора/студента → триггерное удержание |

**Ключевые функциональные требования:**
- FR-001: Прогноз спроса горизонтом 14 дней по слотам (утро/день/вечер) × (CEFR × специализация)
- FR-002: При gap_score > порога → автоматический webhook в маркетинговый кабинет
- FR-003: Lookalike-аудитория пересчитывается раз в 7 дней на основе топ-20% тьюторов
- FR-004: Каждый новый лид получает LeadScore; если score < 0.3 → онбординг адаптируется
- FR-005: P(churn тьютора) > 0.7 в 7 дней → триггер удержания (сообщение + бонус)

**NFR:**

| Требование | Целевой порог |
|-----------|-------------|
| MAPE прогноза спроса | ≤ 15% на горизонте 7 дней |
| Latency LeadScore при регистрации | ≤ 200 мс |
| Частота обновления supply gap map | Ежедневно, batch |

---

### Задача 1 — Tutor Matching (Ранжирование)

**Суть:** подобрать тьютора за ≤ 30 секунд от нажатия «Начать сессию» — персонализированно под уровень, цель, акцент и историю студента.

**Тип задачи:** Learning-to-Rank (LambdaRank / LightGBM), двухэтапная архитектура:

```
[Student profile] + [Tutor pool]
        ↓
  FAISS ANN поиск (эмбеддинги, L2-дистанция)
        ↓
    Топ-50 кандидатов
        ↓
  LightGBM LambdaRank (фичи совместимости)
        ↓
  Business rules фильтр (доступность, рейтинг ≥ 4.0)
        ↓
     TOP-3 тьютора → UI
```

**Фичи:**
- Студент: CEFR level, goal, native_lang, session_count, preferred_time_slots, topic_history
- Тьютор: specializations[], accent_type, avg_rating, rebook_rate, availability_now, response_time_avg_sec
- Interaction: P(student liked similar tutor), skip_rate, rebook_count(student, tutor)

**Ключевые FR:**
- FR-101: Подбор тьютора за ≤ 30 сек от запроса
- FR-103: При отсутствии тьюторов — предложить ближайший слот (≤ 15 мин)
- FR-105: Логирование skip_rate и accepted_tutor_id для дообучения (ежедневный batch)

**NFR:**

| Требование | Целевой порог |
|-----------|-------------|
| P95 latency матчинга | ≤ 500 мс |
| Rebook rate (цель) | ≥ 40% |
| Fairness (Gini тьюторов) | ≤ 0.4 |
| Частота переобучения | Еженедельно (≥ 500 новых сессий) |

---

### Задача 2 — ASR: Транскрипция речи

**Суть:** автоматическая транскрипция речи студента — необходимый слой для LLM-фидбека.

**Тип:** Speech-to-Text (Whisper large-v3) + Silero VAD (разделение студент/тьютор).

**Пайплайн:**
```
Аудио (WebRTC, 16 кГц) → Silero VAD → Whisper large-v3
    → Post-processing (пунктуация, disfluency detection)
    → Транскрипт студента → Задача 3
```

**NFR:**

| Требование | Целевой порог |
|-----------|-------------|
| WER для EN-речи | ≤ 8% |
| Latency транскрипции 30-мин сессии | ≤ 90 сек |
| Стоимость на сессию | ≤ 0,5 ₽ (30 мин × $0.006/мин) |
| Хранение аудио | Удаление через 90 дней (152-ФЗ) |

---

### Задача 3 — LLM-фидбек: оценка речи

**Суть:** автоматический детализированный разбор речи по 4 параметрам CEFR (Fluency, Accuracy, Vocabulary, Pronunciation) с конкретными рекомендациями.

**Тип:** NLP / LLM (генерация) — GPT-4o API со структурированным промптом.

**Промпт-архитектура:**
```json
SYSTEM: Ты — эксперт по оценке разговорного EN по CEFR.
USER: Транскрипция: {transcript}, Уровень: {CEFR}, Цель: {goal}
OUTPUT (JSON):
{
  "fluency_score": 7,
  "accuracy_score": 6,
  "vocabulary_score": 8,
  "pronunciation_markers": ["th-sound", "word stress"],
  "recommendations": ["...конкретные примеры из транскрипции..."],
  "next_topic_hint": "Business negotiations vocabulary"
}
```

**NFR:**

| Требование | Целевой порог |
|-----------|-------------|
| Latency генерации | ≤ 30 сек |
| Стоимость GPT-4o на сессию | ≤ 5 ₽ (~$0.05) |
| 👍-rate пользователей | ≥ 75% |
| Hallucination rate | ≤ 3% |

---

### Задача 4 — Recommendation Engine: следующая сессия

**Суть:** после каждой сессии система рекомендует тему, формат и тьютора для следующей — превращая разовый визит в регулярную привычку.

**Тип:** Гибридная рекомендательная система — Content-Based + Collaborative Filtering (LightFM).
- **CB-компонент**: темы, близкие к целям и истории студента (эмбеддинги × профиль)
- **CF-компонент**: «студенты, похожие на тебя, после этой темы переходили к...»
- **Холодный старт**: только CB → по мере данных вес CF растёт

**NFR:**

| Требование | Целевой порог |
|-----------|-------------|
| Latency | ≤ 500 мс |
| Click-through rate | ≥ 35% |
| Diversity (разнообразие тем за 4 сессии) | ≥ 3 разных категории |
| Частота переобучения CF | Еженедельно |

### Сводная таблица ML-задач

| Задача | Тип ML | Модель | Бизнес-эффект | Приоритет |
|--------|--------|--------|--------------|---------|
| **0** Supply-Demand | Forecasting + Classification + Embeddings | LightGBM / Prophet / Two-Tower | CAC -20–30%; dropout -25–40% | Must Have (до запуска) |
| **1** Tutor Matching | Learning-to-Rank | LightGBM LambdaRank + FAISS | Wait ≤ 30 сек; rebook ≥ 40% | Must Have (MVP) |
| **2** ASR | Speech-to-Text | Whisper large-v3 | Основа фидбека; WER ≤ 8% | Must Have (MVP) |
| **3** LLM-фидбек | NLP Generation | GPT-4o API | Retention +X%; NPS ↑ | Must Have (MVP) |
| **4** RecSys | Hybrid RecSys | LightFM (CB+CF) | Sessions/мес ↑; churn ↓ | Should Have (мес 4+) |

### Конкурентный анализ

| Платформа | Matching | ASR+Feedback | RecSys | РФ |
|-----------|---------|-------------|--------|-----|
| Cambly | Случайный | Нет | Нет | Ушли 2022 |
| italki | Ручной | Нет | Нет | Оплата недоступна |
| Skyeng | Алгоритм (расписание) | Нет | Базовый | ✅ |
| SmallTalk2Me | AI-only | ASR+GPT | Базовый | ✅ |
| **SpeakUP** | ✅ LightGBM LambdaRank | ✅ Whisper+GPT-4o | ✅ LightFM | ✅ |

**Вывод:** ни один конкурент не сочетает on-demand живого тьютора + ML-матчинг + ASR/LLM-фидбек + доступность в РФ.

### Фаза 4 — Оценка и валидация (нед. 12–16)

**Hard gates перед A/B-тестом:**

| Задача | ML-метрика | Минимальный порог | Целевой |

---

### Фаза 5 — Интеграция и A/B-тест (нед. 14–20)

**Архитектура интеграции:**
```
ML Service (FastAPI, Docker)
    ↓ API Gateway (Kong / Nginx)
    ↓ Backend (Node.js / Python)
    ↓ Mobile App / Web (React Native)
```

Каждый ML-сервис деплоится независимо (микросервис) с fallback на rule-based baseline.

**A/B-тест дизайн:**

| Задача | Гипотеза | Метрика успеха | Выборка | Длительность |
|--------|---------|--------------|--------|-------------|
| Matching | ML → rebook rate выше | +10 п.п. vs control | 400 студентов (200/гр.) | 3 недели |
| LLM-фидбек | AI-фидбек → retention D14 выше | +5 п.п. | 600 студентов | 4 недели |
| RecSys | Рекомендация → CTR выше | ≥ 35% vs ≤ 8% | 300 студентов | 2 недели |

**Критерий остановки:** p-value < 0.05, двусторонний тест; MDE ≥ 5 п.п.  
**Guardrail-метрики (нельзя ухудшать):** session_completion_rate, NPS, churn.

---

### Фаза 6 — Запуск в продакшен (нед. 18–22)

**Canary release:** 5% → 48 ч мониторинга → 20% → 50% → 100%.  
**Rollback:** деградация ключевой метрики > 5% → откат за < 15 мин (feature flag).

**Продакшн-инфраструктура:**
```
Yandex Cloud
├── Kubernetes — оркестрация сервисов
├── PostgreSQL — профили, сессии, фидбеки
├── Redis — Feature Store (online)
├── FAISS index — ANN matching (rebuild ежедневно)
├── Kafka — стриминг событий (клики, сессии)
├── S3 — аудио сессий (TTL 90 дней)
└── Grafana + Prometheus — мониторинг
```

**Чеклист перед запуском:**
- [ ] Нагрузочный тест: 100 concurrent сессий
- [ ] P95 latency соответствует NFR (matching ≤ 500 мс, feedback ≤ 30 сек)
- [ ] Алерты на деградацию бизнес-метрик настроены
- [ ] Rollback протестирован (< 15 мин)
- [ ] Аудио шифруется; удаление через 90 дней (152-ФЗ)
- [ ] A/B-тест показал статистически значимый прирост

---

### Фаза 7 — Мониторинг и дообучение (нед. 20–∞)

**Три уровня мониторинга:**

**Уровень 1 — Инфраструктура (Prometheus + Grafana):** CPU/RAM/latency, uptime ≥ 99.5%, throughput.

**Уровень 2 — Качество моделей:**

| Метрика | Алерт при | Инструмент |
|--------|---------|-----------|
| Data drift (PSI фич) | PSI > 0.2 | Evidently AI |
| WER транскрипции | > 10% на выборке | Ручная разметка 50/нед |
| LLM 👍-rate | < 65% за 7 дней | In-app rating |
| NDCG@3 матчинга | < 0.55 на тест-сете | Еженедельный batch-eval |

**Уровень 3 — Бизнес-метрики (Amplitude/Mixpanel):**
- rebook rate ≥ 40%, Retention D7/D30, NPS ≥ 50, churn ≤ 5%/мес

**Стратегия дообучения:**

| Условие | Действие | Частота |
|---------|---------|--------|
| ≥ 500 новых сессий | Полное переобучение Matching | Еженедельно |
| Data drift PSI > 0.2 | Срочное переобучение | По триггеру |
| Новая специализация тьютора | Обновление фич + дообучение | По событию |
| Новая версия Whisper | A/B-тест, при WER↓ → замена | По релизу |

---

### Риски и митигация

**Технические:**

| Риск | Вероятность | Митигация |
|-----|------------|---------|
| Холодный старт matching (мало данных) | Высокая (мес. 1–2) | Rule-based baseline при < 500 сессий |
| Деградация ASR на российском акценте | Средняя | Fine-tuning Whisper на 500 размеченных сессиях |
| Hallucination GPT-4o | Средняя | Structured output JSON; каждая рекомендация = цитата из транскрипта |
| Latency > 500 мс при росте пула | Средняя | FAISS ANN + Redis кэш топ-50; горизонтальное масштабирование |
| Сбой data pipeline → нет фидбека | Низкая | Kafka retry; graceful degradation (сессия засчитывается, фидбек позже) |

**Бизнес:**

| Риск | Вероятность | Митигация |
|-----|------------|---------|
| Supply gap: тьюторов нет при запросе | Высокая (старт) | Задача 0 предупреждает заранее; минимум 50 тьюторов до публичного запуска |
| Отток тьюторов (мес. 1–3) | Высокая | Гарантированный минимум сессий для топ-20%; churn-модель + превентивное удержание |
| Рост цен OpenAI API | Низкая | Self-hosted Whisper в плане; fallback на Llama 3.1 при > 5× росте стоимости |

## 4. Связь ML-метрик с бизнес-метриками

### Логика трансляции

```
Улучшение ML-метрики
    ↓
Улучшение качества продуктового действия
    ↓
Изменение пользовательского поведения
    ↓
Финансовый результат (ARPU, LTV, CAC, выручка)
```

---

### Задача 1 — Matching: ROC-AUC → rebook rate → LTV

| ROC-AUC | Качество matching | rebook rate | Sessions/мес | ARPU/мес | LTV (6 мес) |
|---------|-----------------|------------|------------|--------|-----------|
| 0.50 (случайный) | Baseline | 15% | 1,2 | 600 ₽ | 3 600 ₽ |
| 0.65 (минимальный) | Rule-based | 23% | 1,8 | 900 ₽ | 5 400 ₽ |
| **0.75 (целевой)** | **LightGBM v2** | **32%** | **2,5** | **1 250 ₽** | **7 500 ₽** |
| 0.82 (зрелая) | 6+ мес данных | 40% | 3,1 | 1 550 ₽ | 9 300 ₽ |

**Вывод для CFO:** переход от случайного matching (AUC=0.50) к целевому (AUC=0.75) увеличивает LTV **в 2.1×** — с 3 600 ₽ до 7 500 ₽ на пользователя.

### Задача 1 — Matching: NDCG@3 → конверсия «открыл → оплатил»

| NDCG@3 | Позиция 1 = «правильный» | CTR позиции 1 | Session start rate | Конверсия |
|--------|------------------------|-------------|-----------------|---------|
| 0.40 | 35% | 52% | 68% | 18% |
| 0.60 | 55% | 63% | 76% | 24% |
| **0.75 (цель)** | **70%** | **71%** | **83%** | **30%** |

**Вывод для CPO:** NDCG@3 от 0.40 до 0.75 поднимает конверсию с 18% до 30% — **+67% выручки с того же трафика** без роста CAC.

### Задача 2 — ASR: WER → 👍-rate фидбека → NPS

| WER | 👍-rate LLM-фидбека | NPS | Отток из-за «плохого AI» |
|-----|-------------------|-----|----------------------|
| 20% (без fine-tuning) | ~45% | ~20 | ~12%/мес |
| 12% (Google STT baseline) | ~58% | ~32 | ~8%/мес |
| **8% (Whisper fine-tuned, цель)** | **~75%** | **~50** | **~4%/мес** |
| 5% (зрелая) | ~82% | ~60 | ~2%/мес |

**Вывод:** WER 12% → 8% снижает отток вдвое. На 1 000 пользователей — **+40 000 ₽/мес** экономии на оттоке.

### Задача 3 — LLM-фидбек: Precision → retention D30

| Precision | Recall | F1 | 👍-rate | Retention D30 | Sessions/мес |
|---------|--------|----|---------|--------------|-----------| 
| 0.50 | 0.70 | 0.58 | 42% | 22% | 1,4 |
| 0.70 | 0.70 | 0.70 | 60% | 30% | 1,9 |
| **0.80 (цель)** | **0.65** | **0.72** | **75%** | **38%** | **2,5** |
| 0.85 | 0.75 | 0.80 | 82% | 44% | 3,0 |

**Приоритет: Precision ≥ 0.80** (лучше пропустить ошибку, чем указать несуществующую). Retention D30: 22% → 38% = **+80 активных пользователей на 30-й день** когорты 500 студентов.

**Вывод:** Precision@3: 0.08 → 0.35 увеличивает ARPU на **+67%** при нулевом изменении CAC.

### Итоговый ответ для инвестора

**Вопрос CFO: «Когда окупится?»**  
Совокупный эффект при достижении целевых ML-метрик: ARPU вырастает с ~600 ₽ до ~1 750 ₽ (+192%), retention D30 с 22% до 38%, CAC снижается на 66%. На когорте 1 000 пользователей — **дополнительная выручка ~1,15 млн ₽/мес** относительно нулевого ML.

**Вопрос CPO: «Какую задачу делать первой?»**  
Приоритет — Matching (ROC-AUC), наибольший мультипликативный эффект: rebook rate → sessions → ARPU → LTV одновременно. ASR вторым — фундамент для LLM-фидбека.
