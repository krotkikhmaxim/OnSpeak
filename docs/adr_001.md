# ADR-001: Переход на FAISS ANN + Redis Cache в Matching Service (MDD)

## Метаданные

| Поле | Значение |
|------|----------|
| ID | ADR-001 |
| Дата | 27.05.2026 |
| Статус | Принято |
| Автор | ML Team OnSpeak |
| Метод | Metrics-Driven Development (MDD) |

---

## Context

ML Matching Service OnSpeak систематически нарушает SLO по latency: P95 ~4.15 сек при целевом SLO ≤ 2.5 сек. Причина: полный перебор тьюторов в PostgreSQL при каждом запросе (O(n) сложность).

Предложена улучшенная архитектура: FAISS ANN-индекс + Redis-кэш топ-50 кандидатов. Для обоснования миграции проведён MDD-анализ по двум наборам метрик latency (n = 500 000 каждый).

### Статистика двух систем

| Метрика | Существующая | Улучшенная | Изменение |
|---------|-------------|------------|-----------|
| Mean latency | 3.501 сек | 2.000 сек | -1.501 сек (-42.9%) |
| Std latency | 0.396 сек | 0.401 сек | стабильно |
| P95 latency | 4.152 сек | 2.661 сек | -1.492 сек |
| P99 latency | 4.407 сек | 2.944 сек | -1.464 сек |
| SLO P95 ≤ 2.5 сек | **НАРУШЕН** | **ВЫПОЛНЕН** | SLO восстановлен |

---

## Decision: Гипотезы и статистический тест

**H0:** Среднее latency улучшенной системы ≥ существующей (улучшения нет).

**H1:** Среднее latency улучшенной системы < существующей (улучшение достоверно).

**Уровень значимости:** α = 0.05

### Тест 1 — Welch t-test
Нормально распределённые данные, разные дисперсии.

| Параметр | Значение |
|----------|----------|
| t-статистика | 266.22 |
| p-value | 0.00e+00 |
| **Вывод** | p-value < 0.05 → **H0 ОТВЕРГАЕТСЯ** |

### Тест 2 — Mann-Whitney U
Непараметрический тест для проверки устойчивости результата.

| Параметр | Значение |
|----------|----------|
| U-статистика | 9.96e+07 |
| p-value | 0.00e+00 |
| **Вывод** | p-value < 0.05 → **H0 ОТВЕРГАЕТСЯ** (результат подтверждён) |

### Итоговое решение

**H0 отвергается** на уровне значимости 0.05 по обоим тестам. Улучшенная система статистически значимо снижает latency:

- Mean: 3.50 сек → 2.00 сек (-43%)
- P95: 4.15 сек → 2.66 сек
- SLO восстановлен

**Решение:** МИГРИРОВАТЬ на FAISS ANN + Redis cache через canary 5% → 100%, мониторить guardrail-метрики (rebook rate, completion rate).

---

## Consequences

### Положительные

- P95 latency -36%, SLO выполнен
- Снижение нагрузки на PostgreSQL (ANN заменяет O(n) перебор)
- UX: студент получает список тьюторов быстрее

### Риски

- FAISS-индекс требует ежедневного пересчёта → Airflow DAG 02:00, алерт при failure
- Дополнительная RAM Redis ~500 МБ при 5000 тьюторов → приемлемо

### Следующая итерация (ADR-002)

При > 5000 тьюторов — partitioned FAISS (по специализации) для дальнейшего снижения latency.

---

## Отклонённые альтернативы

| Альтернатива | Причина отклонения |
|-------------|-------------------|
| Горизонтальное масштабирование (больше реплик) | Не устраняет O(n) сложность; дороже |
| ScaNN (Google) | Сложнее в эксплуатации; FAISS достаточен при < 50k тьюторов |
| Полный кэш пар студент-тьютор | Экспоненциальный рост памяти; не масштабируется |
| Async matching (отложенный) | Degraded UX: пользователь видит spinner; неприемлемо |
